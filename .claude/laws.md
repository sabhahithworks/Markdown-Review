# Laws

This table is this repo's review laws. `MARKDOWN_REVIEW_PRD.md` and `docs/plans/README.md` stay the
source for the reasoning; each row here is the checkable form of a rule stated there or in `CLAUDE.md`.

| id | rule | why | scope | enforced_by | severity |
|---|---|---|---|---|---|
| L-no-network | Shipped code makes no network call and carries no telemetry or analytics. The Mermaid file is exempt from the name ban; the pane's CSP blocks every connection (release-expansion D21) | the README promises it is absent, not opt-out | `src/**`, `media/src/**` | scripts/check-bundles.mjs, src/test/csp.test.ts | blocker |
| L-corrupt-sidecar-backup | A corrupt sidecar is backed up to `.json.bak` and the user is told; it is never discarded | a dropped sidecar loses the user's comments | `src/store/**` | src/test/integration/suite/store.spec.ts | blocker |
| L-version-skew-refused | A sidecar with an unknown `version` is refused, backed up and explained; it is never dropped or silently rewritten | PRD §11: version skew must not lose data | `src/store/**` | src/test/reviewFile.test.ts | blocker |
| L-never-auto-delete-comment | No comment is deleted automatically, and `resolved` is set only by a user action | comments are the user's data and inference is only a suggestion | `src/store/**`, `src/detect/**`, `src/anchor/**` | src/test/reanchor.test.ts | blocker |
| L-webview-security | The webview keeps a strict CSP with a per-load nonce, `localResourceRoots` limited to `media/` and the target file's folder, DOMPurify on all rendered HTML, external links through `vscode.env.openExternal`, and no `eval` | the pane renders untrusted markdown (PRD §6) | `src/panel/**`, `src/render/**`, `media/src/**` | review | blocker |
| L-innerhtml-sanitized-only | `innerHTML` is assigned only the sanitized renderer output or a Mermaid SVG that has been through DOMPurify; every other piece of UI is built with `createElement` and `textContent` | an unsanitized string in `innerHTML` is script injection in the pane | `media/src/**` | review | blocker |
| L-lazy-activation | `activationEvents` is exactly `onWebviewPanel:markdownReview.panel` and `workspaceContains:.reviews/*.json`, with no `onStartupFinished` or language event | anything broader wakes the extension at startup; dropping the first breaks panel restore (Plan 04 §10 D24), dropping the second hides the indicators until a pane opens (product-improvements D3) | `package.json` | src/test/integration/suite/activation.spec.ts | major |
| L-vscode-free-core | A module on the `eslint.config.mjs` restricted-import list does not import `vscode` | vitest cannot import `vscode`, so these modules must stay unit-testable | `src/anchor/**`, `src/render/**`, `src/prompt/**`, `src/detect/**`, `src/store/sidecarPath.ts`, `src/store/reviewFile.ts`, `src/panel/messages.ts`, `src/panel/notices.ts` | eslint.config.mjs | major |
| L-block-offsets-single-source | The webview reads `data-ap-start` and `data-ap-end` and never derives block boundaries itself; `walkSpans` stays the one producer for both the plain text and the rendered blocks | a second opinion about where blocks begin breaks anchor offsets (Plan 03 §9) | `media/src/**`, `src/render/**` | media/test/anchorSpace.test.ts | major |
| L-theme-vars-only | Webview CSS takes every colour from a VS Code theme variable; no hardcoded colour | a hardcoded colour breaks in other themes and in high contrast | `media/**` | scripts/check-css-colors.mjs | major |
| L-state-not-by-colour-alone | A status or highlight state is never conveyed by background colour alone | forced-colors mode strips backgrounds, so the state disappears (Plan 06 H17, H19) | `media/**` | review | major |
| L-uncertain-position-shown | A located anchor with confidence below 0.5 is shown as "position uncertain" in text | PRD §5: a weak match must not look like a sure one | `media/src/**`, `src/anchor/**` | media/test/cards.test.ts | major |
| L-prompt-prose-only | The review prompt never asks the agent for markers, ids, replies or structured output | prose-only is what keeps the extension agent-agnostic (PRD §1) | `src/prompt/**` | review | major |
| L-sidecar-path-separators | Sidecar naming normalises path separators on every platform | Windows separators are a flagged bug source in the PRD | `src/store/sidecarPath.ts` | src/test/sidecarPath.test.ts | major |
| L-reanchor-perf | `reanchor` of 50 comments on a 5 MB document finishes under 500 ms | PRD §5 performance target | `src/anchor/**`, `src/render/**` | src/test/perf.test.ts | major |
| L-bundle-size | Each shipped bundle stays under its cap in `scripts/check-bundles.mjs`; a cap is raised only with a stated reason | a quiet size jump usually means an accidental dependency (Plan 05 §8); the package budget is 2 MB (release-expansion D11) | `src/**`, `media/src/**`, `package.json`, `scripts/check-bundles.mjs` | scripts/check-bundles.mjs | major |
| L-message-guard | Every message from the webview passes `isWebviewMessage` before the host uses it, and restored panel state passes `isPanelState` | webview input is an untrusted boundary | `src/panel/**` | src/test/messages.test.ts | major |
| L-watcher-and-debounce | Change detection listens to both the document change event and a `FileSystemWatcher`, debounced through `CHANGE_DEBOUNCE_MS` | agents write to disk without the file being open in an editor (PRD §8) | `src/detect/**` | src/test/integration/suite/detection.spec.ts | major |
| L-baseline-stays-on-host | `baselineText` never crosses to the webview; `reviewState` carries a `ReviewSummary` | it is a whole-document snapshot and the message goes out on every state change (Plan 04 §10 D3) | `src/panel/**`, `media/src/**` | review | major |
| L-single-review-store | `ReviewStore` is the only holder of a review's state; a panel renders what the store posts and keeps no copy of its own | two panels on one file must agree (PRD §11) | `src/store/**`, `src/panel/**` | review | major |
| L-no-retain-context | `retainContextWhenHidden` is not set; reload survival goes through `WebviewPanelSerializer` | PRD §6, unless profiling proves it necessary | `src/panel/**` | review | major |
| L-harness-shell-in-step | `dev/harness/index.html` carries the same shell as `ReviewPanel.getHtmlForWebview` | a stale shell stops the bundle booting, and every harness scenario then passes while testing nothing (Plan 06 H33) | `src/panel/ReviewPanel.ts`, `dev/harness/**` | review | major |
| L-webview-imports-messages-only | Code under `media/src` imports from `src/` only through `src/panel/messages.ts` | any other import pulls host code into the webview bundle | `media/src/**` | review | major |
| L-errors-as-values | Pure modules return a discriminated result for an expected failure and do not throw; only the extension layer turns a failure into a `vscode.window` message | docs/plans/README.md shared conventions | `src/anchor/**`, `src/render/**`, `src/prompt/**` | review | major |
| L-no-new-suppressions | No new `eslint-disable`, `@ts-ignore` or `@ts-expect-error` in shipped code | the count is zero and the definition of done keeps it there | `src/**`, `media/src/**` | review | major |
| L-no-new-deps | No new runtime dependency and no webview framework without the owner's approval recorded in the plan | PRD §3 freezes the stack; the dev toolchain is not part of the freeze | `package.json` | review | major |
| L-prd-non-goals | A PRD §2 non-goal (threads or replies, an MCP server, collaboration, editing in the preview) is not added without asking the owner | they were deferred deliberately | `src/**`, `media/**`, `package.json` | review | major |
| L-fuzzy-corrections-first | A change to `src/anchor/fuzzy.ts` is checked against `docs/plans/01-anchoring-core.md` §9 | two release-blocking PRD defects were found and fixed there | `src/anchor/fuzzy.ts` | review | major |
| L-anchor-space-corrections-first | A change to anchor-space plumbing is checked against `docs/plans/03-commenting.md` §9 | Phase 3 corrected its own plan there | `media/src/anchorSpace.ts`, `media/src/selection.ts`, `src/render/plaintext.ts`, `src/render/renderer.ts` | review | major |
| L-detection-corrections-first | A change to the prompt, the baseline snapshot or status inference is checked against `docs/plans/04-prompt-and-detection.md` §10 | D1 to D24 record the defects real-agent runs found there | `src/prompt/**`, `src/detect/**`, `src/anchor/reanchor.ts` | review | major |
| L-extend-harnesses | Verification is added to `dev/harness/` or `src/test/integration/`; no new harness is built beside them | both were built once and cover what vitest cannot reach | `dev/harness/**`, `src/test/integration/**` | review | minor |
| L-changelog-unreleased | A user-visible change adds a short entry under `Unreleased` in `CHANGELOG.md` | part of the definition of done for a phase | `src/**`, `media/**`, `package.json` | review | minor |
| L-no-vsce-publish | Only the owner publishes to the Marketplace | publishing is the one irreversible step | `**` | guard:vsce publish | blocker |
| L-no-ovsx-publish | Only the owner publishes to Open VSX | publishing is irreversible | `**` | guard:ovsx publish | blocker |
| L-starter-bounded-list | A list that is cut to a limit says it was cut (a count, a "more" marker or a truncation note) | a silently truncated list reads as the whole list | `**` | review | major |
| L-starter-error-path | An error path tells the user what failed and what to do next | a silent or generic failure leaves the user guessing | `**` | review | major |
| L-starter-no-swallowed-errors | No error is caught and dropped; handle it, log it with context, or re-raise it | a swallowed error hides the real failure until it surfaces somewhere else | `**` | review | major |
| L-starter-no-duplicate-helper | A new helper must not duplicate an existing one; search first and reuse or extend | parallel helpers drift apart and fix only one copy of a bug | `**` | review | minor |
| L-starter-tests-assert-values | A test asserts concrete values, not only that a call ran or returned something | a test that checks no value passes on wrong output | `**` | review | major |
| L-starter-limits-in-config | Limits and magic numbers live in config or a named constant, not inline | an inline number can't be found, tuned or explained | `**` | review | minor |
